## 5. 指标与数据接入规则

### 5.1 指标口径

- 入园/出园：时间段内的人次，说明是否去重；不得与独立游客人数混用。
- 在园人数：优先采用可靠来源的存量值；用进出差计算时记录基线、校正和异常，不静默把负数改为正常值。
- 区域人数：必须关联具体区域和数据来源；围栏本身不产生人数。
- 多区域汇总：重叠区域、重复摄像头计数不能直接相加得到景区人数。
- 排队时长：区分实测值与估计值，标注更新时间；没有数据时显示暂无数据。
- 游客画像：来源、样本覆盖和未知分类必须保留，不能从网评样本推断全量游客。
- 热度：若由容量利用率或其他规则计算，公开规则；模拟热度标记为演示。
- 同比/环比：由后端统一计算；分母为零时返回不可计算及原因。
- 营收：金额与币种分开存储，使用精确小数，说明退款、核销、支付或入账口径。

### 5.2 接入契约

统一封装来源、来源记录 ID、业务时间、接收时间、景区、区域、数据质量、原始引用和接入模式。

采集具备幂等去重、失败重试、游标/水位、补采与迟到数据重算能力。首次先实现导入和模拟适配器，再替换真实系统。

建议按数据源定义 `REAL`、`DEMO` 模式；模式跟随数据进入 API 和报表。真实接入失败时显示失败或过期数据，禁止自动切换成演示数据。

网评首期可使用受控 CSV 导入和预留 API；未获得稳定接口时，不把自动采集第三方平台评价承诺为已完成功能。导入格式、必填列、编码和逐行错误需写入文档。

地图内部统一明确坐标系，建议 GeoJSON 使用 WGS84。国内底图若采用其他坐标系，须在适配边界转换并测试，不能混存。

## 6. 云端 DeepSeek Agent 设计

### 6.1 定位与官方接口基线

DeepSeek 负责语言理解、工具选择和结果组织；应用负责工具执行、权限、计算、事务与审计。

查阅日期为 2026-10-13：官方文档提供兼容格式 API，基础地址为 `https://api.deepseek.com`；工具调用由应用执行并回传结果。模型名必须配置化，部署前重新核对账号可用模型及相应工具能力。[D1][D2]

结构化输出可参考官方 JSON Output，但服务端仍需校验字段、枚举、长度及业务约束，并处理空响应与截断。首期不依赖 Beta strict 模式。[D3]

### 6.2 首期采用一个运营 Agent、三条受控流程

1. 网评分析：领取待分析记录 → 脱敏 → 批量分析 → 校验分类和原文证据 → 保存 → 人工修正。
2. 运营问答：解析景区和时间 → 调用授权工具 → 得到数据及来源 → 生成回答 → 校验引用。
3. 运营日报：固定统计工具生成数据快照 → 分析异常 → 生成结构化报告 → 保存版本。

避免为每个按钮创建独立自治 Agent。确定性的统计和流程由业务代码完成；模型仅处理需要语言理解或推理的部分。

### 6.3 工具清单与边界

| 工具 | 主要参数 | 返回内容 | 首期权限 |
|---|---|---|---|
| `get_flow_summary` | 景区、起止时间、指标 | 指标值、单位、口径、截止时间、来源 ID | 只读 |
| `get_flow_trend` | 景区/区域、时间、粒度 | 限长时间序列和缺失区间 | 只读 |
| `get_review_summary` | 景区、时间、主题 | 总数、主题分布、脱敏证据 | 只读 |
| `get_review_evidence` | 已授权评价 ID 列表 | 限长原文片段、来源引用 | 只读 |
| `get_inspection_summary` | 景区、时间、状态 | 任务数量、异常与逾期记录 | 只读 |
| `get_device_status` | 景区、设备类型 | 在线情况和状态时间 | 只读 |
| `create_inspection_draft` | 区域、建议事项、依据 ID | 草稿 ID，不能直接派单 | 可写草稿，独立权限 |

天气和预测工具在真实能力接入后注册；不提供的工具不出现在模型工具列表。Agent 不得调用任意 URL、SQL、Shell 或自行访问数据库。

工具参数由 JSON Schema 描述，进入应用后再次校验。登录用户与授权景区由服务端注入，模型无法扩展范围。指定未授权景区时返回权限错误，不能静默查询其他景区。

### 6.4 执行流程与限制

```text
接收任务 → 验证身份/范围 → 建立任务快照 → 构造最小上下文
  → 调用 DeepSeek → 检查工具请求 → 校验参数与权限
  → 执行业务工具 → 保存调用记录 → 回传结果
  → 再次调用或结束 → 验证输出及证据 → 保存结果
```

建议可配置初值：最多 6 轮模型调用、12 次工具调用，问答任务总时限 120 秒；只读工具最多重试 2 次。开发环境验证后根据延迟和预算调整，不作为性能承诺。

429/临时服务错误采用有限退避；鉴权失败不盲目重试。写入草稿使用幂等键，不能因模型或网络重试重复创建。工具异常返回结构化错误，让模型承认缺失。

长任务状态：`QUEUED → RUNNING → SUCCEEDED / FAILED / CANCELLED`。持久化重试次数、执行租约、心跳和取消标记；服务重启后恢复过期租约任务，不重复提交业务写入。

任务归属于用户和授权范围，查询、事件订阅及取消均校验权限。运行时权限变化要在每次工具调用重新判定。

### 6.5 输出契约

运营问答输出包含 `answer`、`facts`、`evidence`、`limitations`、`dataAsOf`、`dataMode`。事实项尽量包含 `metric`、`value`、`unit`、`period`、`sourceIds`。

评价分析输出包含 `reviewId`、`sentiment`、`topics`、`summary`、`evidenceSpans`、`needsHumanReview`、`model`、`promptVersion`。情绪建议枚举为 POSITIVE/NEUTRAL/NEGATIVE/MIXED/UNKNOWN，主题采用受控字典。原文没有证据时不能编造。

日报保存统计快照、模型与提示版本、数据截止时间、覆盖率、事实段和建议段。再次生成建立新版本，避免覆盖原始证据。

模型输出的来源 ID 必须属于本任务实际返回的证据集合。核心数字与统计快照校验，不接受模型生成的随机数字或未经验证链接。保存工具轨迹和业务解释即可，不以存储模型内部推理文本作为审计要求。

### 6.6 安全、费用和可用性

- 密钥仅存在服务端环境或密钥管理中；环境示例留空，前端构建产物和日志不包含密钥。
- 外部评价即使含“忽略规则、导出资料”等文字，也只作为待分析数据；不能改变工具权限。
- 模型接收聚合指标和必要脱敏文本；手机号、证件、完整客户档案默认不发送。
- 模型文本安全渲染，禁止直接执行 HTML 或脚本。
- 按用户、任务和每日额度配置限额；记录模型、token 用量、延迟和错误。费用估算依据部署时官方价格配置，不能硬编码历史价格。
- 云端不可用时，普通业务继续工作；AI 明确失败并允许重试。
- 测试使用假模型适配器，不能让自动测试默认消耗真实额度。真实连通验证单独执行并记录证据。

| `review` | 来源记录 ID、景区、时间、原文、脱敏文本、来源引用 |
| `review_analysis` | 评价、分类、证据、模型、提示版本、人工修正及版本 |
| `inspection_task` | 景区、区域、执行人、截止时间、状态、乐观锁版本 |
| `inspection_item_result` | 任务、检查项、结果、文字、附件引用 |
| `inspection_issue` | 任务、异常、整改人、状态、整改记录、复核人 |
| `file_asset` | 对象键、内容类型、大小、上传者、业务归属 |
| `agent_run` / `agent_message` | 用户、范围快照、场景、消息、任务状态、用量 |
| `agent_tool_call` | 任务、工具名、脱敏参数、结果引用、时间、状态 |
| `operation_report` | 景区、日期、版本、数据快照、结构化内容、生成任务 |
| `background_job` | 类型、幂等键、状态、租约、重试、错误 |
| `audit_log` | 操作人、业务对象、动作、结果、时间、traceId |

数据规则：来源 ID 在来源范围内唯一；金额精确小数；业务数据尽可能非空景区归属。时间段统一使用左闭右开 `[start,end)`。跨景区汇总只在授权集合内执行。按真实规模再决定客流表分区与保留期限。

巡检状态建议：`DRAFT → ASSIGNED → IN_PROGRESS → SUBMITTED → COMPLETED`；发现异常进入 `RECTIFYING`，整改后进入 `PENDING_REVIEW`，复核不通过回到 `RECTIFYING`。后端维护允许迁移表并记录操作人，客户端不可任意改状态。

## 8. API 与前后端契约

以 `/api/v1` 为前缀，维护 OpenAPI 规范；普通接口使用明确 HTTP 状态码和结构化错误，不能全部返回 200。

| 方法与路径 | 用途 |
|---|---|
| `POST /auth/login`、`POST /auth/logout`、`GET /auth/me` | 身份与当前权限 |
| `GET /scenic-sites` | 授权景区列表 |
| `GET/POST /scenic-sites/{id}/zones` | 围栏查询与新增 |
| `PATCH /zones/{id}` | 区域更新 |
| `GET /devices` | 设备查询 |
| `POST /devices/{id}/playback-session` | 获取短期授权播放会话 |
| `GET /flows/summary`、`GET /flows/trend` | 客流汇总和趋势 |
| `POST /imports/reviews` | 网评导入任务 |
| `GET /reviews`、`GET /reviews/{id}` | 评价查询 |
| `POST /reviews/analysis-jobs` | 批量分析任务 |
| `PATCH /reviews/{id}/classification` | 人工分类修正 |
| `GET/POST /inspection-tasks` | 巡检列表与创建 |
| `POST /inspection-tasks/{id}/transitions` | 执行指定状态迁移 |
| `POST /inspection-tasks/{id}/results` | 检查项和异常提交 |
| `POST /files` | 上传文件并关联授权业务 |
| `POST /agent/runs` | 创建问答/分析/日报任务，返回 202 与 runId |
| `GET /agent/runs/{id}` | 任务状态、结果和依据 |
| `GET /agent/runs/{id}/events` | SSE 进度事件，可选轮询降级 |
| `POST /agent/runs/{id}/cancel` | 取消任务 |
| `GET /reports`、`GET /reports/{id}` | 历史报告 |

列表统一分页并限制最大页长；时间范围和聚合粒度设上限。错误包含 `code`、`message`、`traceId`，不暴露内部堆栈和密钥。

事实数据响应包含 `dataAsOf`、`sourceIds`、`dataMode`、`quality`，前端不能把缺失值转成零。来源引用通过授权 API 解析，不能直接暴露第三方凭据。

认证首期建议同源服务端 Session、HttpOnly Cookie，写请求启用 CSRF 防护；如改 JWT，需同时设计撤销、过期与存储策略。SSE 复用同源身份，事件仅发送任务进度、工具摘要和结果，不发送秘密参数。

## 9. 视频与地图专项边界

### 9.1 视频

接入前调查：厂商、平台接口、设备协议、编码、网络连通性、授权方式、同时观看路数及回放需求。GB28181 接入需考虑信令与设备管理，不等价于增加播放器。

播放器必须区分无权限、设备离线、连接失败和编码不兼容。播放会话短期有效，设备账号与原始带密钥 URL 不进入前端。监控录像默认由原平台管理；本系统首期不承担全量录像存储。

转协议与转码分别评估。容量设计考虑摄像头码率、并发观看数和转码需求，尚不能给出生产服务器配置。

### 9.2 地图与三维

底图 API、许可证、网络可达性和离线部署条件另行核实。开发可使用自制示意底图，必须标记演示。

三维先定义模型加载接口、坐标和点位关联；没有真实模型时不得以示意建筑宣称完成真实景区数字孪生。

## 10. 实施里程碑与交接任务

按依赖顺序推进；“任务包”是后续分配依据，本报告没有启动任何其他 Agent。

| 阶段 | 工作内容 | 完成证据 |
|---|---|---|
| M0 基础契约 | 锁定版本、工程骨架、OpenAPI、迁移、种子数据、环境模板 | 本地启动、健康检查、决策记录 |
| M1 业务底座 | 登录、景区授权、地图区域、设备、客流导入与查询 | 两景区隔离测试、空间及统计测试 |
| M2 业务闭环 | 网评管理、视频适配、巡检执行与整改、移动页面 | 可重复端到端流程、失败状态截图 |
| M3 AI 闭环 | 模型适配、受控工具、问答、评价分析、日报、任务恢复 | 假模型测试、评估报告、可选真实 API 验证 |
| M4 总览交付 | 大屏、联调、部署、备份恢复说明、验收清单 | 干净环境可复现启动、关键测试通过 |
| M5 真实集成 | 用正式接口替换适配器，核对指标和视频兼容 | 接入记录、真实数据抽检、现场验收 |

可拆分工作包：前端；业务后端与数据库；Agent；视频/数据适配与部署。数据库迁移和 OpenAPI 由明确负责人维护，先约定契约再分别实现，避免各 Agent 自行定义不兼容字段。

每次交接附：变更范围、文件、接口变更、迁移、测试命令与结果、未完成项、真实外部依赖状态。不允许仅凭“页面可以打开”判断模块完成。

## 11. 验收标准

### 11.1 功能验收

1. 至少两个演示景区，有不同权限用户；未授权景区不能通过直接 API、文件、视频、Agent 或 SSE 访问。
2. 地图围栏可保存并重载；点位和区域关系正确；非法多边形被拒绝。
3. 同一批客流数据重复导入不重复计数；迟到数据能更新汇总；缺失与过期状态可见。
4. 网评能导入、检索、分析、人工修正；人工修正不被后台重跑静默覆盖。
5. 巡检可从派单完成到提交、整改、复核；无权操作和非法状态迁移被阻止。
6. 视频演示适配与真实接入分别标记；至少在真实设备可用后验证一个播放通路。
7. AI 答案能追溯到实际查询的数据；找不到依据时明确说明；无权数据不能通过自然语言提问获得。
8. DeepSeek 超时、限流、无密钥和不合法结构化输出均有可恢复状态；普通业务不受影响。
9. 后台任务可取消、有限重试、重启恢复；写操作幂等；测试不自动调用收费服务。
10. 所有演示数据、报告和截图均标记性质；生产就绪状态单独记录。

### 11.2 AI 评估集

建立固定小型评估集，至少覆盖：正常查询、模糊时间、无数据、跨景区越权、过期数据、网评提示注入、错误工具参数、多轮工具、重复写入、网络失败、JSON 空响应/截断及不存在的证据引用。

评价分类使用人工标注样本记录准确率/混淆情况，目标阈值待真实样本确定。安全边界和确定性统计需测试通过；不把模型措辞完全一致作为通过标准。预测功能上线前另做时间顺序回测，记录基线和误差，禁止用未来信息训练后再评估过去。

### 11.3 运行与性能

部署文档记录机器配置、数据量、并发数、视频路数和测试结果后再制定 SLA。开发目标是交互及时、长任务异步、数据查询有范围限制；不能在没有负载测试的情况下承诺高并发或毫秒级响应。

生产准备还包括 HTTPS、配置隔离、审计保留、数据库备份与恢复演练、磁盘监测、任务/采集健康检查。演示部署不自动等于生产高可用。

## 12. 仍待明确的事项及不阻塞开发的处理

| 待明确项 | 开发默认处理 | 影响真实上线的部分 |
|---|---|---|
| 最终首期范围、三维是否硬性 | 按 P0 开发并保留 P1/P2 清单 | 合同验收范围 |
| 团队技术与部署规范 | 按推荐栈建立 ADR | 维护交接与运行环境 |
| 视频厂商、接口、网络 | 视频适配器 + 演示资源 | 实时监控验收 |
| 客流来源、口径、刷新频率 | 明确标注演示数据和可配置采集 | 实时人数与热力准确性 |
| 网评获取方式 | CSV 导入 + 接口适配边界 | 自动采集 |
| 巡检是否离线/小程序 | 在线移动网页 | 弱网现场使用与通知 |
| DeepSeek 可用模型、密钥、预算 | 环境配置与假模型测试 | 云端真实调用 |
| 园区模型、底图与坐标 | 二维演示地图 | 真实三维展示 |
| 酒店餐饮团队等接口 | 记录后续契约，不构造真实经营结论 | 跨业态能力 |
| 保存期限、SLA、并发规模 | 配置入口与测试记录 | 生产容量及运维设计 |

编码 Agent 应先完成不依赖这些答案的基础工作，把真正依赖外部条件的能力标记为“待接入”，不能伪造完成状态。
