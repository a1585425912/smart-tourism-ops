# 数据来源与许可

| 数据 | 来源 | 许可 | 在系统中的用途 | 性质 |
|---|---|---|---|---|
| 地图要素（景区边界、水系、道路、建筑轮廓、兴趣点） | OpenStreetMap，经 Overpass API 抓取，脚本 `scripts/data/fetch_osm.py` | ODbL 1.0，需署名 “© OpenStreetMap contributors” | 景区边界、二维底图、三维建筑拉伸、业态点位位置 | 真实开放数据（快照时间见 GeoJSON 的 `osm_base`） |
| 哈尔滨逐日气象 2023-01 起 | Open-Meteo Historical Weather API | CC BY 4.0 | 预测特征、日历天气 | 真实再分析数据 |
| 法定节假日与调休 | 国务院办公厅通知，经 holiday-cn 项目整理 | MIT | 预测特征、日历 | 真实 |
| 客流、排队、区域人数 | 系统内置仿真模型 `DemoFlowModel` | — | 全部客流相关功能 | **仿真**，标记 DEMO |
| 网评 | 系统生成的合成评价文本 | — | 网评分析、AI 评估 | **仿真**，平台名称仅作标签 |
| 酒店/餐饮/零售经营、旅行社团队、游客画像 | 系统内置仿真规则 | — | 业态与团队分析 | **仿真**，商户与旅行社均为“（演示）”虚构名称 |
| 视频画面 | 前端绘制的模拟画面 | — | 点位监控演示 | **仿真**，带“演示画面”水印 |

景区容量、开放时间、区域划分、设备点位都是演示配置，不代表景区官方数据。

仿真客流使用真实的节假日和气象作为驱动因素（春节、周末、极寒、降雪等），所以预测模型能学到有意义的规律。但回测误差只能说明方法和流程可用，不代表在真实客流上能达到同样精度。

接入真实数据时，新增一个调用 `FlowIngestService` 的适配器并停用对应的 `flow-demo-*` 数据源即可。系统不会在真实接入失败时自动切换回演示数据。
